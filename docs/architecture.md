# Ballast architecture

Ballast covers one narrow peril: an autonomous agent causes an unauthorized debit of a third party’s own native GEN funds during the policy period. The canonical incident is the finalized top level Studio transaction sent by the insured executor; its child transfer receipts cannot create additional loss identities. The spend must exceed its registered authority, cause a measurable loss to a third party and be supported by public evidence. The maximum cover is 100 Studio GEN. Studio GEN has no monetary value.

The browser handles email login, forms and displaying state. The Next.js server verifies Privy access tokens, stores encrypted per user signing keys in Neon and relays explicitly requested actions. It never uses the deployer key for user actions. An idempotent operation ledger records submissions and receipts. A hash identifies each immutable manifest. Private evidence is not supported; users must explicitly acknowledge that submissions are public.

The registry stores the manifest, operator address and a permanent loss record. Underwriting independently evaluates declared capabilities, past losses and public peer evidence. Exact risk bands map to deterministic premium rates. Capital providers choose a junior or senior tranche. Active limits are fully reserved before binding. Tranche share prices absorb losses, junior first; premiums accrue by a fixed split. Withdrawals preserve policy specific backing and premium locks within each tranche. Exhausted share generations cannot block new capital.

The court stores claims and resolves one finding at a time: harm, causation, declared scope and payout band. Every validator fetches the sources and reaches its own decision. Booleans match exactly and the payout band matches exactly. Reasons are saved for people to read but do not enter the equality test. Individual unavailable sources are tolerated if two reachable hosts remain. Otherwise review pauses for bounded evidence repair; overdue unresolved cases can close without a merits decision. The v1 peril pays only when harm and causation are true and declared scope is false. A proven loss caps the requested claim; the payout band selects 0, 25, 50, 75 or 100 percent of that cap.

Distinct losses may use a policy concurrently, sharing its aggregate limit. A rejected claim preserves cover; a payout reduces remaining cover. Each party retains an independent bonded appeal for every boolean and each payout revision. The initial decision has a 24 hour challenge period. Appeals reopen that period. Anyone may finalize after it closes. Settlement is pull based: the court marks a final verdict; underwriting reads it, updates reserves, credits the claimant and indexes the complete operator loss record. Quotes read this record directly so an omitted registry synchronization cannot hide losses. The registry reads the pool’s authoritative operator record and can independently index individual settlements once. Authoritative cross contract reads consume authenticated finalized message confirmations. The supported default storage view exposes these immutable proofs; raw court status is insufficient. [The finality design](finality.md) explains the protocol dependency and the Studio storage limitation. A settlement confirms its proof before queuing a court acknowledgment, with permissionless recovery if delivery fails. Expiry requires a confirmed cumulative filing seal and subtracts requests already settled locally. That acknowledgment removes the case from account recovery indexes and reduces aggregate requested exposure. It never determines payment.

Studio transfers are simulated. Payouts and capital withdrawals use a native transfer from the pool and show both the accounting result and transaction receipt. The deployment verification checks the actual runtime behavior before publication.
