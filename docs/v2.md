# Ballast v2

Ballast v2 uses four GenLayer intelligent contracts. The registry records a stable executor identity and immutable manifest revisions. Assurance independently judges public evidence. Underwriting consumes finalized passports and authoritative loss records. The court establishes facts and loss amounts; compensation follows a deterministic rule.

## Trust passports

The public `/agents/:id` page and `/api/v2/agents/:id/passport` endpoint expose scope clarity, spending controls and observed behavior. Each finding is `supported`, `contradicted` or `insufficient`. Reasons and per-source SHA-256 digests are retained on the assurance contract. The assessment history endpoint accepts a bounded cursor and a catalog deployment ID.

An operator requests an assessment using public evidence from at least two normalized hosts. Each finding is evaluated separately, and validators independently retrieve and evaluate its evidence. Mere repetition across hosts does not establish independent corroboration. Missing sources cannot establish a favorable history.

Each finding permits one public challenge and one operator appeal. The 0.01 GEN bond is recorded before a separate permissionless judgment transaction, so a transient provider failure cannot lose the challenge. Changed findings return the bond; an upheld public challenge awards it to the operator, while an upheld operator appeal awards it to the configured treasury. The 24-hour public challenge window and seven-day review deadline are fixed. Pending challenges refund at timeout. Final decisions use authenticated self-messages emitted on transaction finalization; a permissionless publish action repairs missing confirmations.

A passport is valid for seven days from its request. New assessments, challenges, stale evidence and missing finality confirmation stop new underwriting. Policies retain the manifest, assessment revision and peril version they bound. Monitoring cannot rewrite an existing policy.

## Cover and claims

The peril remains an unauthorized native Studio GEN debit of a third party's own escrow, tied to the initiating executor transaction. V2 quotes require a fresh, finalized, complete passport plus independently evaluated peer evidence and finalized loss accounting in the configured preceding pools. Base rates remain 2%, 5% and 10%, with the existing loss surcharge and 20% cap.

V2 court findings are harm, causation and scope. Positive harm requires consensus on exact realized loss and event time. The court calculates the smaller of the requested amount and the evidenced uncompensated loss when harm, causation and a scope breach are established. The pool independently checks those facts and caps settlement at remaining policy cover. There is no LLM payout percentage. One claimant receives at most one award for a transaction across the configured generations. Filing bonds, factual appeals, mutual acceptance and permissionless finalization retain their existing protections. Earlier v1 cases retain their fourth payout finding and original rules.

## Sponsored progression

Vercel Workflow reconciles saved user operations, advances permissionless claims and assessments, and checks opted-in monitoring. A daily authenticated Cron dispatch recovers queued or stranded jobs and checks evidence. Changed evidence, manifests or paid-loss counts trigger reviews, otherwise reviews are weekly. Two reachable hosts are required. Source outages pause monitoring without a negative finding.

A dedicated sponsor key is bound into assurance at deployment. It is stored independently from the deployer and user custody keys, and its service account is explicitly identified as `service:ballast:v2`. It never signs a premium, bond, consent or capital action for a user. Pilot admission uses a database row lock for ten subscriptions. An atomic sponsor lease caps new submission attempts at twenty per UTC database day and one transaction in flight; a protocol timeout remains in flight until a terminal receipt. Ready claim work takes priority over assurance and monitoring.

Exact signed payloads, idempotency identities and attempt history use the existing encrypted transaction journal. Jobs preserve pending payloads when dispatch repeats. Each restart has a distinct epoch; failed runs are inspected before restarting. Continuations are saved before enqueueing. Submitted operation actions are persisted atomically with their journal so Cron can recover a missed initial workflow start. Domain ticks wait for authenticated final confirmations before dependent actions.

## Deployment and recovery

`deployments/catalog.json` is the allowlist of immutable generations. `deployments/studio.json` selects current new business. Every preceding generation remains accessible for its capital, credits, policies and unresolved cases. No migration transfers an existing holder's funds. A generation ID cannot select an arbitrary contract address, and deprecated generations reject new registration, capital, cover and monitoring requests.

The database migration is additive and idempotent. Test it with `BALLAST_MIGRATION_SCHEMA=ballast_test_<name>` before applying it to `public`. `scripts/verify-v2-schema.ts` checks required columns. The optional `BALLAST_CURL_DB=1` fallback is local tooling only and sends its confidential connection header through stdin.

Production requires `BALLAST_SPONSOR_KEY`, `CRON_SECRET` and `WORKFLOW_VERCEL_EXPERIMENTAL_START_HOOK=1`, alongside existing variables. Enable Vercel System Environment Variables and use Node 22. Workflow start hooks provide atomic run admission; the database retains business recovery state.

The isolated Studio lifecycle uses fresh test actors and intentionally vulnerable test vaults. Its assurance challenge window is 300 seconds and sponsor cooldown is 60 seconds; only the isolated deployed source is transformed. Production sources retain 24 hours and one day respectively. Live evidence, source hashes, receipts, validator votes and balance checks belong in `docs/v2-integration-result.json`; no unperformed production deadline or customer-account scenario should be reported as tested.
