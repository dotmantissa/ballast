# Reviewer remediation

The review found gaps in real application logic. These changes narrow the promise and put enforceable bounds around it. Direct tests exercise the original failure shapes; they are not presented as proof of live validator decisions.

| Finding | Change | Regression evidence |
| --- | --- | --- |
| Unavailable evidence locks reserves | Reachable corroboration can replace a missing source. Each party can repair evidence without extending the fixed review clock. Withdrawal and permissionless timeout return the filing bond. Distinct claims can proceed together. Runoff retains only aggregate requested exposure up to remaining cover. | Source outage, repair, timeout, independent budgets, concurrent cases, multi case runoff and the maximum 70 day appeal sequence |
| Compensation replay | Exact Studio native debit transaction plus claimant defines the event across agents and policies. Harm assessment independently fetches the official Studio record and requires a finalized top level executor transaction; child receipts are rejected even if the model approves. Assessors establish loss and time. Settlement recomputes identity and enforces a global paid ledger. V1 allows one award per claimant and debit. | Reference aliases, child receipts, wrong senders, unfinalized roots, unavailable chain records, different registrations, hash casing, repeated awards and independently established loss caps |
| Manifest aliases | Stable executor identity, explicit executor authorization, immutable canonical manifest revisions and one active or runoff policy per executor | Whitespace, key order, duplicate JSON keys, ownership theft, overlapping cover, stale quotes and revision A to B to A |
| Appeal preemption | Each party has its own appeal for each boolean and each payout revision. Changed eligibility invalidates payout and clears both parties’ acceptance. | Operator upholding a favorable finding cannot prevent the claimant challenging it |
| Missing policy dates | Every assessment receives the authoritative policy and exact insured manifest revision. Harm must establish the actual timestamp inside those dates. Settlement checks dates again. | False submitted event time, out of period evidence and independent metadata disagreement |
| Junior premium exit | Policy specific junior and senior backing plus premium allocations stay locked in their own tranches. A claim cannot spend another policy’s allocation. | Original 100 senior plus 1 junior example, multi policy locks and loss allocation |
| Appeal evidence omitted | Accepted appeal sources become effective case evidence and are retrieved for every dependent assessment | Scope appeal followed by payout reassessment fetches both added URLs |
| Malformed public URLs | Shared strict public HTTPS parsing and normalized hosts in all contracts. The interface renders malformed records inertly. | Malformed authorities, default port aliases, credentials, private addresses and hostile public record browser checks |
| Wiped tranche cannot restart | Fresh capital starts a new share generation when NAV is zero. Old worthless shares remain inspectable without controlling new capital. | Uncooperative old holders cannot block or dilute recapitalization |
| Older records vanish | Dedicated account indexes, complete unresolved pagination, earlier public pages and direct record lookup | More than 50 stored records, stable cursors and browser recovery of older cases |
| Failed operations never retry | Durable encrypted signed identity before broadcast, fenced attempts, reconciliation for uncertain sends and backoff for safely failed attempts | Actual submit and synchronization code tested with controlled database and chain stand ins; exact byte resume tested separately |
| Nonfinal accounting | Authenticated immutable proofs arrive only from finalized self messages. Settlement requires the court proof, acknowledgment requires the pool proof, and expiry requires a cumulative court filing seal. Studio rejects explicit finalized cross contract storage, documented in the finality design. | Callback authentication, immutable payloads, finalized emission assertions, missing proof refusal, monotonic delayed delivery, cumulative seals and final but unsettled index retention |

The [finality receipt record](review-finality-result.json) verifies actual emitted Studio transactions against their exact finalized parents and authenticated senders. The [finality design](finality.md) explains why this protects accounting on the current Studio host.

All claims share one aggregate policy limit. Finalized settlement order determines access to remaining cover. The court’s assessed award is distinct from the amount actually paid by the pool. Exhausted policies still record zero settlements so later cases do not get stranded. This is disclosed in the interface and terms.

The [completed live lifecycle](review-integration-result.json) uses an intentionally insecure test vault and separate claimant and executor accounts. It produced an actual 0.2 native test GEN debit, four approved findings, an upheld scoped appeal, finalization, settlement and actual claimant payout and bond withdrawals. The native pool balance equals its accounted TVG. The production pool remains separate. No model fixture is counted as a live result.

Production transition preserves existing positions. The earlier production pool held 20 Studio GEN at the final transition inspection, with no policies or claims. The app retains holder initiated redemption and withdrawal against that exact archived address, reports actual balances and marks read failures explicitly. New capital and cover use the corrected deployment. No holder’s funds are moved automatically. The archived contracts retain their earlier code; deployment does not retroactively patch them. The app exposes withdrawal access to that pool, and directs all new capital and cover to the corrected contracts.
